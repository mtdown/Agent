## 0. 结论先行

**不建议把 `qwen3.8-max` 非思考档作为默认生成模型。**

它确实把正确率从 **0.6500 抬到 0.7200（+7.0pt）**，但同一批数据下：

| 判据 | 结果 |
|---|---|
| +7pt 是否统计显著（McNemar） | **不显著**（p = 0.1671） |
| INCORRECT 绝对量 | **20 → 20，一道没修好**（修好 6 题的同时新错 6 题） |
| 误拒率（有答案题） | 5.68% → **25.00%**，校正判据误伤后仍 20.45%，**显著恶化**（p = 0.0029） |
| 引用角标覆盖率 | 0.5993 → **0.5171（−8.2pt）**，配对检验 **t = −3.12 显著下降** |
| 平均耗时 | 4359 ms → **8671 ms（×1.99）**，p95 13.8s、max 62.2s |

即：**用显著的"更爱说依据不足" + 引用支撑变差 + 耗时翻倍，换来一个不显著的 +7pt。**

### 显著性（本次必须给，否则会误读 +7pt）

- **正确率**：McNemar 精确检验，变好 13 题 / 变差 6 题，不一致对 n=19 ⇒ **双侧 p = 0.1671，不显著**。
  （两比例近似 z=1.07，p=0.2852，同结论。）
- **误拒率（判据口径）**：5.68% → 25.00%，z=3.69 ⇒ **p = 0.0002，显著**。
- **误拒率（校正后）**：5.68% → 20.45%，z=2.98 ⇒ **p = 0.0029，显著**。
- **引用覆盖率**：逐题配对 n=88，均值差 −0.0822，SE 0.0263 ⇒ **t = −3.12，显著**。

> 样本量红线：n=100（有答案 88），正确率标准误约 ±6.5pt。
> **差值 < 5pt 一律不作改进证据**；本次 +7pt 虽超线，但配对检验不显著，仍**不能**当作改进。

### 判决迁移矩阵（行=基线，列=非思考臂）

| 基线 \ 非思考 | CORRECT | PARTIAL | INCORRECT |
|---|---|---|---|
| **CORRECT** | 59 | 1 | 5 |
| **PARTIAL** | **9** | 5 | 1 |
| **INCORRECT** | 4 | 2 | **14** |

读法：
1. **+7pt 的唯一来源是 PARTIAL → CORRECT 的 9 题迁移**（减掉反向的 1+1）。
   也就是说，它没有"补上不会的题"，只是把"列了证据但没下结论"变成了"下结论"。
   这与**上沿持平 0.8000** 完全自洽：证据覆盖面没有变宽，只是更敢下结论。
2. **INCORRECT 两臂都是 20 题，净变化为零**。基线错、方案修好的 6 题
   （MHR-0555 / 1385 / 1678 / 2054 / 2437 / 2529）被基线对、方案新错的 6 题
   （MHR-0855 / 0880 / 1288 / 1840 / 1875 / 2069）完全抵消。
   ⇒ **没有任何一类系统性错误被修好，只是换了一批错题。**

## 3. 误拒率为什么翻了两番：一半是真信号，一半是判据缺陷

判据是**零 LLM 成本的两级规则**（`run_ask_eval_mhr.py: is_refusal`）：7 条强短语正则 + 1 条弱短语正则，
规则为「有信号 **且**（首个陈述句含强短语 **或** 全文无带角标陈述）⇒ 判拒答」。
逐题取证后，22 题误拒分三类：

| 类别 | 题数 | 含义 |
|---|---|---|
| 真失败并如实声明 | 13 | 判官判 INCORRECT —— 确实没答对 |
| 部分作答 | 5 | 判官判 PARTIAL —— 只答了多问中的一问 |
| **判据误伤** | **4** | **判官判 CORRECT，答案其实给对了** |

4 例误伤全部是同一形态：模型把规范措辞当成了**口头禅式开头**，后面照样作答。例如：

- `MHR-0258`：开头「根据现有资料，未能找到相关依据。」→ 随后明确答出
  「体育博彩公司（sportsbooks）」，与 gold 一致，判官判 CORRECT；
- `MHR-0232`：开头「根据现有资料未能找到相关依据。」→ 随后给出完整对比并结论「不存在分歧的依据」，
  与 gold（no）一致；
- `MHR-0312`：同形态，结论「并不存在金额不同的情况」与 gold（no）一致；
- `MHR-2216`：措辞出现在句中描述某个子细节（"这一细节现有资料未能找到相关依据"），
  主体答案是 Epic Games，正确。

⇒ **判据缺陷已精确定位到一行合取条件**（`eval/scripts/diag/diag_refusal_path.py` 已逐题复现决策路径）：

```python
def is_refusal(text):
    """两级：有信号 +（首句强短语 或 全文无带角标实质陈述）才判拒答。"""
    signal = refusal_signal(text)
    if not signal["strong"] and not signal["weak"]:
        return False
    statements = split_statements(text)
    if not statements:
        return True
    if refusal_signal(statements[0])["strong"]:
        return True                      # ← 缺陷在这行：不再要求"其后无实质陈述"
    return not [s for s in statements if CITATION_MARKER_RE.search(s)]
```

**第一分支一命中就 return，第二分支（全文无带角标陈述）永远轮不到。**
本臂 22 题里，**每一题的首个陈述句都正好是那句套话**（模型的习惯性开头），
于是 22/22 全部由第一分支判出，与后文是否作答无关。
取证结果：4 例被误伤的题「首句有强短语 = True」且「全文带角标陈述 = 2~5 条」，仍被判拒答。

**正确修法**：第一分支补上合取条件，即「首句强短语 **且** 其后无带角标实质陈述」才判拒答；
或把判据改成要求"套话之后没有任何实质作答"。注意基线臂同样会被该分支命中（5 题首句均含套话），
所以**两臂同时受影响**，只是本臂套话开头更频繁（22 次 vs 5 次）导致绝对量放大。

**校正后的口径仍然显著恶化**（18/88 = 20.45%，p = 0.0029），所以这不是纯度量假象。
补充两条：

1. **该措辞是真实的失败信号**：带措辞题的正确率 0.1818（4/22），不带措辞题 0.8485（66 题中 56 对）；
   基线臂同向（0.0000 vs 0.6386）。⇒ 判据有用，但**误报率 4/22 ≈ 18%**。
2. 基线臂 5 题误拒中**没有一题**是判官判 CORRECT 的，误伤为 0。

本报告同时给出两个口径，避免拿一个口径比另一个口径。
（对照：中文侧 `run_ask_eval.py` 的判据已带同一条"首句/全文"结构规则，但中文侧的规则方向是先查全文 —
英文侧这一行的短路顺序把它变成了"首句命中即终局"，是移植时的语义漂移。）

| 环节 | 自证方式 | 结果 |
|---|---|---|
| 环境变量真的透到请求体 | **负控**：把模型名设为不存在的 `model-does-not-exist-xyz` 跑 1 题 | 后端返回 `LLM 响应异常 HTTP 404: The model \`model-does-not-exist-xyz\` does not exist...`（DashScope 兼容端点 OpenAI 风格报错）⇒ 变量确实生效且 base-url 已指向 DashScope |

| 检索侧确实没被动过 | 后端日志关键字计数 | 多查询分支日志 0 条、证据整理日志 0 条、LLM 错误 0 条 |

## 5. 未完成臂：`qwen3.8-max` 思考档 —— **阻塞，无数据**

设计里另有一条"开思考"臂（不设 `RAG_LLM_ENABLE_THINKING`，走模型默认即开思考）。
该臂跑到第 14 题时**主动终止**，未落盘任何结果，原因是一个真实缺陷：

- `RagAskServiceImpl.java:66` 硬编码 `new SseEmitter(120_000L)`，**不可配置**；
- 开思考后单题耗时实测 **11.5s ~ 126.7s**，13 题里 5 题 > 90s；
- 超过 120s 的请求触发 `AsyncRequestTimeoutException`（后端日志 2 次，14 题中占 14%），
  经 `emitter.onTimeout` → `future.cancel(true)` **直接掐断仍在流式的 LLM 调用**；
- runner 侧该题记 `rec["error"]`、判官置空、**不计入 answered**，只进 `errorCount`。

被砍掉的恰好是**思考最久的那批题**，属于结构性缺失 ⇒ 该臂即便跑完也**不可用于对比**。
因此止损（当时 14/100），按 AGENTS.md 第 4 节先汇报、待确认后再决定是否改造后重跑。

> 附带的真实产品影响：前端用户问一个需要长推理的问题时，同样会在 120s 处收到
> 被掐断的 SSE 流，而不是完整答案或明确超时提示。这是一个独立于本实验的缺陷。

## 6. 不可比性声明

1. **判官与回答模型同家族（对方案臂不利）**：非思考臂回答模型是 `qwen3.8-max`，
   判官是 `qwen3.8-flash` —— **同一家族**，存在自我偏袒、把 +7pt 抬高的可能；
   基线臂回答模型是 DeepSeek，与判官不同家族。⇒ **+7pt 若真有，也应打折看**；
   反过来说，误拒率与引用覆盖率的**恶化**是在"偏袒方案臂"的前提下测出来的，方向更可信。
2. **与历史 0.55 不可比**（同样是 2026-09-17 探索性跑批，题目集只 2 题重叠、未落盘逐题答案）。
3. **本报告不给"检索层 vs 答案层"的合并分**：两层互不合并是项目既定约束。
4. **判官仍是 LLM**：已知它会漏判"列出相符证据但未明说结论"的答案，故 0.65 / 0.72 都是
   严格下沿；两臂同一判官、同一 prompt，**差值方向可信、绝对值不可当真实正确率**。
5. 检索侧两臂完全一致（MQ off / 整理 off），故差异可归因于生成模型；
   但这只覆盖"生成模型"这一个变量，**不能据此推断检索层或整体方案优劣**。
