# Design

## Context

见 proposal.md。当前 Cloud `/agent/stream` 只转发 query，Agent 每次新建模型历史；前端 Agent 消息只存在内存。Cloud 已有登录态、空间可见性与 RAG 搜索，Agent 内部服务不直接接触用户权限。

## Goals / Non-Goals

**Goals:** MySQL 为会话和消息的唯一持久来源；Cloud 在调用 Agent 前完成归属与空间权限检查；历史有限截取，引用逐消息保存并恢复。

**Non-Goals:** 自动知识库 Skill、对话向量化、跨用户共享、跨会话长期记忆。

## Decisions

1. **Cloud 持有会话。** 新增会话、消息表及所有者限定查询；列表、详情、删除和 SSE 发送接口都从登录态取 userId，绝不相信前端传来的 ownerId。相比把历史留在浏览器或 Agent，这能统一授权和持久化。
2. **一轮请求明确表示 RAG 模式。** `OFF` 跳过检索，`ALL` 使用当前全部可见空间，`SELECTED` 要求非空空间 ID 列表且与可见空间求交。只有 `ALL` 才可向旧检索服务传空 `spaceIds`；`SELECTED` 交集为空立即拒绝/返回无依据。这样避开旧服务“空列表即全部”的语义陷阱。
3. **按轮保存快照。** 用户问题先入库，成功完成才保存 assistant 正文、引用元数据和 token/耗时。失败轮标记为失败；后续上下文只读取成功完整的轮次。记录的引用用于展示，点击仍走现有文档鉴权接口。
4. **Cloud 编排，Agent 生成。** Cloud 将最近有限轮已完成消息及本轮检索依据发送到仅内部访问的 Agent；Agent 的系统提示区分对话历史与当前检索证据，保留当前 SSE 事件格式。相比 Agent 自行检索，权限实现只有一处。
5. **前端分开经典 RAG 和 Agent 状态。** Agent 显示本人会话列表与新会话入口，允许当前轮 RAG 范围选择；每条 assistant 消息独立持有引用。经典 RAG 页面逻辑不改。
6. **历史列表与标题。** Agent 模式在聊天区左侧显示“新聊天”和历史条目；条目右侧菜单提供重命名、删除，所有操作按当前用户鉴权。创建时由 Java 显式写入 UTF-8 标题，首问覆盖默认标题；启动时仅对已知乱码默认标题按首问修复，保留手动改名。数据库建表脚本使用 ASCII 默认值，避免平台编码影响。
7. **流式超时。** Cloud 与内部 Agent 的 MVC 异步请求超时均大于 Agent 循环的 120 秒上限，Cloud 还留出代理与持久化余量。
8. **Agent 模型名称。** Agent 使用 DeepSeek Chat Completions；默认模型改为官方当前支持的 `deepseek-flash`，保留 `RAG_LLM_FAST_MODEL` 环境变量的显式覆盖能力。经典 RAG 模型配置不随本次变更。
9. **模型流读取期限。** DeepSeek 流式接口可先返回 HTTP 200，再以 `: keep-alive` 等待推理。`HttpRequest.timeout` 不会中断已经开始的响应体行读取，因此 Agent 需在自身截止时间主动关闭上游 SSE，并返回明确错误帧。对 DeepSeek 模型显式关闭默认思考模式并限制每轮最大输出，符合本阶段快速对话的预期。

## Risks / Trade-offs

- [数据库迁移尚未执行] → 提供幂等 DDL，先在本地执行再启动服务；回滚保留数据，应用可回退至旧版本。
- [SSE 断连时无法确认完成] → 只在收到 Agent 完成事件后标记回答成功；失败状态不进入下一轮上下文。
- [会话长导致 token 增长] → 仅携带最近几轮且限制字符数，后续上下文控制阶段可再优化。
- [旧引用被删除或失权] → 保留展示快照，但文档导航继续使用当前鉴权接口。

## Migration Plan

先部署两张新表，再部署 Agent 内部结构化输入与 Cloud 编排，最后部署前端。回滚时前端及服务可回到旧接口，新表暂时保留以免丢失对话数据。
