# Design

## Context

参见 proposal。三个角色共享任务分支及工作区，根 `AGENTS.md` 会作为共同指导，角色文件须在派单时明确要求读取。当前 change 属于 `feature/agent-development-workflow开发`，现有未提交草稿为本次修订基线，须保留并核对。

## Goals / Non-Goals

**Goals:** 固定总管、开发、测试的交接契约；让测试结果绑定被测内容；记录可观察的通过、失败及阻塞证据。

**Non-Goals:** 不实现调度程序、不创建 Git worktree、不修改业务代码及现有脚本；不承诺共享工作区具备文件级盲测隔离。

## Decisions

1. 根规则区分共同规则与仅总管执行的规则；派单显式指定角色文件。相比将整份根规则都定义为父智能体规则，这可避免角色职责串用。
2. 总管制定固定 acceptance、验证方式、边界和任务卡，开发负责代码与必要测试及自检。每轮总管新建不继承开发或上一轮测试对话的测试实例，并记录实例身份；不可创建时阻塞。上下文隔离不意味着共享文件隔离。
3. 每轮记录基线提交、文件清单和含新增文件的被测快照或完整 diff；开发停止写入，测试前后检查内容一致。基线比较仅在需要且可安全执行时进行，未执行不能推断失败是既有问题。
4. 测试固定验收并提供证据。清单外重大回归单独记录并阻断交付，由总管仲裁或升级；风格意见不作为失败。命令无法证明行为时为证据不足。
5. 普通已解决试错记录在回执；需长期追踪的问题、测试 FAIL、阻塞及重大风险记录 IssueLog 和证据，需要代码对照时使用 HTML。开发和测试按交接顺序写入共享报告。
6. 总管核对报告及证据；证据矛盾、高风险或负责人要求时才追加独立复核。保持三轮上限：首次测试为第一轮，实现修改后的再次测试递增；纯环境恢复或补证据不增加开发轮次，但不得复用测试实例。
7. 文件数超过 10 只提示影响面检查，不独立构成停止条件；依赖、CI/CD、迁移、公开 API、验收歧义仍按负责人既有规则升级，已预先明确授权的范围除外。
8. 分阶段经独立测试 PASS、必要复核及阶段检查后，由总管检查 `git status` 与 `.gitignore` 并使用 `upload.ps1` 推送；不得合并 main。当前任务草稿在同一语义阶段处理，不能未经核对使用 `git add -A`。

## Risks / Trade-offs

- [共享工作区泄露历史记录] → 测试实例不继承对话，承认文件并不盲测，限制输入并记录快照。
- [验收遗漏重大风险] → 独立报告并阻断交付，不擅自改写固定验收。
- [测试结果与被测版本不一致] → 快照标识与前后内容校验，不匹配则证据不足。
- [上传混入已有改动] → 核对完整文件清单及本阶段范围后才上传；范围不明时停止。

## Migration Plan

更新三份规则，独立验证其相互一致与场景覆盖后按阶段上传。回滚时恢复变更前的三份规则，保留实际生成的问题记录和验证证据。
