# Spec Delta

## Purpose

规定总管、开发与独立测试智能体在共享工作区中的任务交接、证据管理与阶段交付，以确保任务可执行且验收结果可追溯。

## ADDED Requirements

### Requirement: 角色职责与任务卡
规则 MUST 区分共同规则及三个角色职责；总管 MUST 提供任务边界、固定验收、验证方式和角色文件，开发 MUST 实现并自检，总管不得代替独立测试宣布通过。

#### Scenario: 开发任务派发
- **WHEN** 总管派发开发任务
- **THEN** 任务卡包含身份、范围、契约、固定验收、验证前提、命令和预期，并明确要求读取开发角色规则

### Requirement: 独立测试与被测内容
每轮测试 MUST 使用新的、不继承开发和前一轮测试对话的实例；测试 MUST 绑定基线和包含新增文件的被测快照，测试期间相关文件不得被开发者改写。

#### Scenario: 测试实例或快照不可用
- **WHEN** 无法建立独立上下文或无法确认被测内容
- **THEN** 测试报告阻塞或证据不足，不能记为通过或上传

### Requirement: 验收和重大风险
测试 MUST 为每项验收记录实际操作、预期、实际和证据；清单外重大回归 MUST 单独报告并阻断交付，风格意见不得作为失败依据。

#### Scenario: 验收外发现重大回归
- **WHEN** 测试发现有证据支持的重大回归但它未列入固定验收
- **THEN** 测试记录风险与证据，总管暂停上传并仲裁或升级，不擅自更改固定验收

#### Scenario: 验收证据不充分
- **WHEN** 验证无法执行或结果不能证明预期行为
- **THEN** 结论为证据不足而不是 PASS

### Requirement: 修复循环和记录
测试失败 MUST 附原始证据与复现条件交还开发；每次修改后的复测 MUST 新建测试实例，同一原子任务最多三轮，第三轮仍失败须停止并上报。问题记录 MUST 区分普通试错与需要追踪的问题。

#### Scenario: 修复后复测
- **WHEN** 开发完成失败修复
- **THEN** 总管提供原固定验收及新的被测快照，派发全新测试实例

### Requirement: 阶段交付
总管 MUST 检查测试证据、变更范围与工作区，按风险决定是否追加独立记录复核；通过后方可使用项目上传脚本推送任务分支。合并 main MUST 获得负责人明确授权。

#### Scenario: 报告存在证据矛盾
- **WHEN** 测试结论与证据不一致
- **THEN** 不上传，追加独立复核或补充证据后重新判断
