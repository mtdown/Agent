## Why

项目已经建成完整的 RAG 评测能力——99 题数据集（五类题型）、双适配器 runner、可复现的指标口径——但**这套流程只存在于脚本注释、`changes/` 工件和对话记录里**：换一个人拿到仓库，无法照着复现；想改任何一环（切块参数、embedding 模型、题型配比），也没有地方能查到影响面。

同时对外文档停在 Wiki 阶段：根 `README.md` 把已经实现的 RAG 标为「🚧 规划中」，技术亮点 7 条**没有一条**是 AI 相关，反而保留了一条**仓库内无实测来源**的性能声明（「纳秒级延迟、百万级吞吐」）。

**能力已经具备，但不可讲（README 滞后）、不可维护（流程无权威说明）、对外不一致（含无依据声明）。** 这三条正好卡住求职引用与协作交接。

## What Changes

- **`eval/README.md` 增补两个章节**：端到端评估流程（语料 → 数据集 → 运行 → 报告，含每步的输入、命令与产出物），以及「改动影响面」映射表（想改 X → 动哪些文件 → 需要重跑什么）
- **清理 `eval/results/`**：移除本地 embedding（Ollama 2560 维）与离线预演两份历史结果，只保留当前云端基线 `baseline-20260912-151958-http.json`（DashScope `qwen3.7-text-embedding-flash`，1024 维）
- **重写根 `README.md` 的项目现状**：RAG 由「规划中」改为已实现；补 RAG 链路、开放 API、评测体系三块内容；技术亮点增补 AI 类条目
- **删除** README 中无实测来源的性能声明（「纳秒级延迟、百万级吞吐」）
- 同步路线图勾选状态与项目结构（补 `eval/`、`cloud/.../rag/`）

## Capabilities

### New Capabilities

- `rag-eval-flow`: 评估流程的单一权威说明、改动影响面映射、对外引用基线的唯一性与模型归因要求，以及对外文档与项目实际状态的一致性约束

### Modified Capabilities

无。本次不改任何系统行为，只约束文档、数据归档与基线口径。
