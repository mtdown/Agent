# Proposal

## Why

Agent 创建 Wiki 文档时，提交后响应丢失无法区分成功与失败；现有未知状态阻止继续写入，但无法安全恢复结果。需要以可复查的本地基线和分阶段对照验证改进，并保留失败安全边界。

## What Changes

- 先在隔离本机环境测量现状，记录注入点、次数、持久化结果及限制，不修改产品行为。
- 为 Agent 单篇 Wiki 文档创建引入稳定操作标识、数据库约束及原子结果记录；旧请求保持原有语义，不宣称获得幂等保证。
- 增加受内部身份认证和当前权限约束的状态查询；对不确定结果只做有限查询恢复，不能确认时保留 unknown，不盲目重试。
- 通过本机独立验收记录四个阶段的原始证据及简历可引用口径；博客素材只读取并用于隔离测试。
- 不涉及批量网页导入、文件夹创建、任意 Wiki 写入或线上部署。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-wiki-write`: 为 Agent 单篇文档创建增加可选幂等操作标识及权限受控的状态恢复，维持现有创建和展示约束。

## Impact

L2：影响 cloud_agent 工具调用、cloud 内部创建及查询契约、MySQL 迁移、权限检查和测试；不改变既有对外客户端必填字段。可能影响缓存、索引副作用和故障恢复；独立记录限制。需要回滚开关与兼容部署顺序，保留操作记录及已创建文档，禁止以回滚删除用户数据。所有服务和文档写入测试仅限本机隔离资源；不上传博客内容或访问线上服务。
