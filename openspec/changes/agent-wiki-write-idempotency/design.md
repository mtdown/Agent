# Design

## Context

`AgentWikiCreationService.createDocument` 使用 READ COMMITTED、空间行锁和写前权限检查，文档事务提交后清缓存；Agent 通过内部 HTTP 网关调用，未知写结果使本轮后续写入停止。原流程不携带持久操作身份。既有文件夹创建、网页导入、前端展示及无操作 ID 的旧调用须保持语义。

## Goals / Non-Goals

目标是在单篇 Agent Wiki 创建的边界内实现幂等及受控结果恢复，并在本地隔离环境记录真实阶段证据。不覆盖文件夹、批量、跨会话用户手动重提、外部索引或缓存的 exactly-once；不从正文推断用户意图。

## Decisions

1. **操作身份与兼容**：Agent 在调用单次文档创建前生成不可猜测 UUID，绑定该次已解析的用户、空间、文件夹及规范化请求；同一次传输恢复保留该 ID，不由模型提供或凭内容生成。不同工具调用即使正文相同也产生不同 ID。仅扩展内部请求的可选字段 `operationId`，旧请求不传时走原路径，原返回结构不删除字段；旧请求不具备新保证。禁止在网页导入及其他工具中复用。
2. **数据库事务**：新增操作表，唯一约束 `(user_id, operation_id)`；保存版本化摘要、目标、结果 ID 和完成信息，不保存正文。摘要采用稳定 UTF-8、字段长度界定的规范编码，涵盖 spaceId、folderId、title 的 null/空区别与 content。创建文档、记录结果在同一 MySQL 事务中提交或回滚。唯一约束与锁协调并发，重复请求在独立事务中读取已提交结果；不能因为锁等待超时、记录未出现或事务未提交而认定失败。请求同 ID 不同摘要返回明确冲突且不创建。表持久保留，不自动过期或删除；如未来需要清理须另议。
3. **权限和信息边界**：内部调用沿用现有服务间认证和服务端注入用户身份，ID 不授权访问。首次创建、重复返回和状态查询均检查当前身份与目标当前访问权限；撤权、目录/文档删除或移动时拒绝或返回不含目标内容的不可访问状态，不重建文档。不同用户不得借 ID 发现操作是否存在，禁止泄露正文、原始 ID 于用户可见文本或日志；内部 ID 序列化为十进制字符串。
4. **恢复协议**：内部新增查询接口，按当前用户和操作 ID 查询，返回 `SUCCEEDED` 与允许访问的创建结果，或不区分不存在、未提交、无权限的不可确认状态。超时后 Agent 有界查询（最多 3 次、间隔 200ms；每次独立超时），成功则按已有结构化结果处理；查不到或查询失败仍返回 `unknown` 并执行原有写入阻断。不得因查询不到自动创建新 ID 或重新写入；结果确认成功不代表缓存或索引完成。状态查询不返回内容摘要或正文。兼容部署时 cloud 先升级并迁移，Agent 发现旧服务不支持查询时保留 unknown；不允许在旧服务上重试并宣称幂等。
5. **本地量化**：固定注入点“数据库提交后丢弃 HTTP 响应”，每组 30 次独立操作；基线与优化组对相同模板及本机博客样本进行相同注入，记录每次 operation、HTTP 次数、数据库新增文档数和用户可见结果。基线不篡改现有 Agent 停止策略；如需测重放，用显式标记的受控相同请求重放单列，不能称自然发生率。另测并发、内容冲突、事务回滚、鉴权及服务重启。无法运行真实数据库则 BLOCKED，不以 mock 代替持久化结论。

## Risks / Trade-offs

- [同事务外缓存/索引不一致] → 不承诺外部副作用 exactly-once；保留现有缓存行为，记录失败，不能重建文档修复缓存。
- [重放与并发] → 唯一约束、事务与摘要共同保护，必须测并发和事务回滚；锁超时保持未知。
- [用户撤权/移动/删除] → 每次结果读取重验权限和当前状态，宁可拒绝恢复，不能暴露旧内容。
- [操作身份丢失] → 本次仅保障同一次工具调用的内存上下文；跨进程或跨会话自行重提不在保障范围，重启后可由持有原 ID 的受信内部调用查询。
- [身份和数据泄露] → 仅传本地测试素材，不把博客原文、token、个人信息和线上地址写入报告。

## Migration Plan

本机先备份并核验隔离数据库，执行可重复/可检测的增量建表迁移，再部署兼容 cloud，最后启用 Agent 新路径。回滚先停用 Agent 恢复和 ID 发送、回退应用到兼容版本；保留新表和已提交文档以免重复与丢数据。停止所有新路径并备份后，只有负责人明确批准且确认无未决操作时才考虑移除表；回滚不自动删除数据。迁移前后及故障注入均禁止指向线上实例。缓存与索引恢复不属于本次原子性保证。
