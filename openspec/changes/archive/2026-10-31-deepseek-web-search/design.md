# Design

## Context

Agent 在 cloud_agent 中通过注册表声明和执行模型工具，使用流式循环；既有模型密钥可能用于其他兼容服务。用户授权搜索与抓取，并要求区分摘要与正文。

## Goals / Non-Goals

目标是有界地使用 DeepSeek 原始 JSON API，保留来源并在失败时诚实降级。不增加界面开关、数据表或公开 HTTP 接口，不做后台抓取或自动写入知识库。

## Decisions

- Search 和 Fetch 是独立只读工具，复用现有工具循环；工具提示引导模型根据需要搜索、仅在摘要不足或用户给出链接时抓取。可选方案是只搜索，但无法按需读取指定页面。
- 独立配置 `DEEPSEEK_WEB_API_KEY`，空值禁用联网工具，不复用可能属于其他服务的模型密钥；基址固定 DeepSeek，测试通过注入客户端地址，不在前端传递密钥。每轮绑定独立预算：Search 和 Fetch 各最多 3 次上游 HTTP 尝试，重试计入预算；不跨用户共享状态或缓存。
- Search 默认 5 条、need_content=false，输出保留标题、URL、摘要及是否有正文；Fetch 仅允许无凭据的 HTTP(S) URL，长度不超过 8192。对输入、响应字节、超时和传给模型的文本设置上限。HTTP 408、429、5xx 可在预算内最多重试一次，其余错误不重试。禁止记录密钥及原始网页正文。
- 提示模型把网页视为不可信数据，优先附实际来源；正文缺失时注明仅依据摘要，细节无法核实时如实说明。模型生成不可完全由提示保障，测试使用可控模型检验提示与数据流，不声称消除提示注入或保证所有引用正确。
- 保持原有身份验证和知识库权限；用户问题或 URL 发送到 DeepSeek，网页内容进入模型上下文。无新增持久化、共享缓存和数据库变更。

## Risks / Trade-offs

- [第三方调用产生费用和披露搜索词或 URL] → 每轮硬预算、独立密钥及停用方式；真实调用仅在具备环境及验证必要时执行。
- [外部网页指令污染或来源错误] → 将内容限定为不可信证据、限制大小并保留实际 URL；生成结果仍需审慎使用。
- [上游不可用或正文缺失] → 返回分类失败，允许说明仅基于摘要或无法确认。

## Migration Plan

部署时通过环境变量注入密钥，未设置时保留已有 Agent 行为；回滚可移除密钥禁用工具或回退本变更。无需数据库迁移。
