# Proposal

## Why

Agent 已有联网和 Wiki 基础能力，但现有网页导入服务尚不能被 Agent 直接调用，系统提示也混杂多个流程，导致用户目标与结果状态容易被误解。

## What Changes

- 增加受控 Agent 网页导入工具，复用既有 Wiki 链接导入和身份、权限校验、来源记录及逐项结果。
- 为网页导入和现有 RAG 问答提供内置工作流 Skill，精简系统提示，保留一般对话及既有工具能力。
- 对用户指定的现有目录直接导入网页；内容撰写使用既有任务文件夹流程。
- 按负责人确认，只重试导入后缓存清理；重试仍失败时保留异常并同时报告已保存与缓存未刷新，不重复创建文档。
- 按负责人确认，Agent 内部使用逐项成功、明确失败、未知和未执行状态并明确事务边界，保留现有公开导入接口的字段与两态语义。
- 按负责人确认，扩大相关 Wiki 删除、成员权限及目录变更的并发一致性范围，配合导入的事务边界进行真实 MySQL 验证；不修改公开接口。
- 按负责人确认，排查并修复基线会话持久化映射测试与现有实现的冲突，保留会话行为和原固定验收。
- 按负责人确认，Agent 网页导入在任何实际写入前显示待确认的空间、目录和链接，由登录用户明确确认；取消或未确认不写入，服务端而非模型验证确认。

## Capabilities

### New Capabilities
- `agent-wiki-workflows`: Agent 网页导入和基于现有 RAG 证据问答工作流。

### Modified Capabilities
- `agent-wiki-write`: 明确网页导入可使用用户指定的既有目录，既有内容撰写流程不变。

## Impact

Cloud 内部 Agent 入口、cloud_agent 工具和提示词、内置 Skill、用户确认交互与相关测试；确认流程复用现有选择接口的 URL、请求字段和事件流，新增导入确认交互类型及对应行为，是公开交互数据契约扩展。原有选择行为兼容，不新增数据库迁移或第三方依赖。保留现有 RAG 页面控制及无结果短路行为。
