# Design

## Context

Wiki 现有 URL 导入按用户权限与可选目录直接抓取并保存，Agent 当前仅能让模型读取截断网页或创建文档。RAG 由 Cloud 在模型前按页面开关和授权范围运行，空结果直接答复。既有 Wiki 答复通过结构化投影隐藏内部 ID 并处理部分成功。

## Goals / Non-Goals

实现可验证的 Agent 导入及两个内置 Skill，同时保持既有通用 Agent、Wiki 权限和 RAG 行为。不实现代码执行、统一结果库、子目录创建、RAG 自动开启或流式修复。

## Decisions

- 用户于 2026-11-01 确认增加网页导入的写入前确认。模型的请求只形成待确认草案，展示实际空间、目录及完整链接；实际执行须由登录用户确认触发，服务端绑定会话、用户和精确参数并验证有效期与一次性消费，取消、过期、未确认及重复确认均不得写入。内部导入入口不得仅凭模型参数和内部密钥绕过该确认；用户确认后由服务端读取已确认参数执行，并重新校验当前权限及目录。对中断或提交结果未知保留未知且不自动重试，不能将确认或领取当成导入成功。
- 复用现有 `POST /agent/conversations/{id}/wiki-choice/stream` 的 `{turnId, token}` 和事件流，通过服务端持久交互的类型区分已有空间选择与导入确认；不接受客户端或模型重新提交草案目标及链接。新增 `import_confirmation` 的交互类型和前端确认卡片，保留原选择类型与行为；这是事件/历史投影及端点行为的公开契约扩展，前后端须配套部署。确认草案须在卡片可提交之前可靠持久化，防止用户点击早于保存；明确确认/取消、恢复与过期状态，不泄露内部 ID。确认成功并非导入成功，执行中断的未确定项显示未知。原有确认入口使用的最新轮、归属、有效期及原子消费保护应对新类型同样适用。除负责人明确批准调整的摘要误调用验收外，原有验收不变；新增验证覆盖伪造、篡改、并发重复及取消。
- 草案显示的空间和目录路径须与实际写入时的目标一致：对目标空间、目录及祖先的改名/移动，在导入写入边界使用共同的协调锁和当前读取检查；确认后如果显示快照不再匹配，拒绝写入并要求重新确认。对既有目录和空间改名路径补齐必要的锁及复查，并以真实 MySQL 并发测试验证；不改变现有公开接口。
- 将现有 URL 导入服务通过受内部密钥保护的 Cloud 入口提供给 Agent 生成待确认草案，而不是将限长 Fetch 内容交给模型拼装写入。工具接收 spaceId（字符串）、可选 folderId（字符串，根目录省略或 null）及 urls（有界数组），不接受用户 ID；经用户确认后服务端从可信 userId 加载用户，检查当前空间和文件夹权限，复用现有 URL 安全校验、Markdown 提取、来源元数据、缓存和索引逻辑。每项输出输入、状态、标题和字符串 documentId；拒绝的目标不创建任何文档。
- 通过 Wiki 域的别名和已选空间约束处理导入参数，确保内部 ID 不被模型及页面暴露。结构化投影逐项呈现和持久化可确认的结果并使用现有权限/打开机制；对 unknown 保留不确定性，不把失败归为成功。执行中断后部分写入仍可能无法重建，不承诺幂等或新建结果库。
- 定义两项平台内置 Skill：导入 Skill 调用位置选择与导入工具；RAG Skill 仅约束使用已提供的 evidence，不虚构自行检索工具。通过既有 Skill 目录和 get_skill 暴露；在目录有界、用户拥有很多 Skill 时仍应可选择平台内置 Skill。未命中 RAG 的既有服务端短路保持不变。
- 系统指令只保留通用约束、外部资料不可信、结果真实与权限，以及既有其他功能必要契约；细节移至 Skill。模型遵循指令不是安全边界，鉴权、别名、确认和结果投影仍由代码强制执行。用户只要求总结网页时，模型应避免提出导入；即使模型误触发待确认卡片，未经用户明确确认不得写入。
- 与现有 agent-wiki-write 的任务文件夹规则区分：它适用于用户新撰写内容的写入；明确请求导入外部网页并指定已有目录时复用该目录。
- 已确认现有 `saveImported` 先持久化后清缓存，缓存异常被批量循环归为失败。按负责人决定，文档 ID 已确认后仅对缓存清理最多额外重试一次，绝不重试保存；仍失败时保留脱敏的异常诊断并反馈“文档已保存、缓存刷新失败”。确认保存前的异常或无法确认提交的异常分别如实反馈，不能以名称推定保存成功。兼顾已有导入入口，避免修改公开 HTTP 签名；现有返回契约不够表达时停止上报，不私自扩大 API。
- 负责人确认：Agent 使用独立内部结果类型，区分每项成功、明确失败、未知及未执行；公开 URL 导入仍使用原字段和两态返回。复用同一抓取、清洗和 URL 安全核心，不重复下载；在内部路径按项获取受控事务边界，写入前重新核验当前身份、空间及文件夹有效性。事务提交确认为成功之前遇到可能已写入的异常，不凭临时 ID 判断，报告未知并停止后续项及本轮后续写入；其余项标为未执行。结果应经既有安全投影保留每项的显示信息，隐藏内部 ID。
- 权限与目录变更的并发一致性：负责人批准扩大相关共享路径的内部修改，统一明确锁次序与当前读，在获得相关锁后重新检查空间、成员权限、目标目录及删除前计数/树状态，再提交各自事务；覆盖撤权、退出、角色变化、空间删除及目录删除/移动等影响导入的路径。不可仅在导入侧加锁而假定其他写路径自动受保护；无有效用户、空间、成员或目录即拒绝，不依赖不存在记录的间隙锁。锁冲突、死锁或事务异常不得导致虚报成功或自动重复保存；必须使用真实 MySQL 的独立测试数据、可控并发屏障和数据读回验证实际提交顺序、权限及目录状态，测试数据需可安全隔离和清理，环境无法满足时停止报告。确认提交后再清缓存，清缓存重试不重跑保存。客户端连接中断后部分已执行结果可能仍无法重建，不承诺幂等或跨轮结果恢复。
- 基线会话测试冲突：负责人批准核查并修复 `AgentConversationPersistenceMappingTest` 与 `AgentConversationStore` 的不一致。优先保持原测试断言、数据库初始化及历史升级行为和用户可观察行为，避免因全量回归失败而放宽固定验收；不新增迁移或修改公开接口。如原设计或兼容性无法确认，先上报而不是仅删除或弱化断言。

## Risks / Trade-offs

- [网页可能涉及内网目标或大响应] → 复用导入服务全部目标和限额校验，不自行下载或绕过校验。
- [目标目录在查询后失权或跨空间] → 写入时以当前用户重新核查目标，不相信模型给出的归属。
- [导入多项部分成功或 HTTP 中断] → 每项状态真实投影，未知不重试；跨轮事务和统一持久化未包含。
- [保存成功后缓存清理持续失败] → 不重复保存，仅重试缓存清理，保留异常和已保存但缓存未刷新的结果；无法保证旧缓存立即消失。
- [提示精简使其他工具回归] → 保留既有约束并对普通对话、写入和网页搜索进行回归；不声称提示可保证模型选择。

## Migration Plan

部署更新的 Cloud 与 Agent，不迁移数据；回滚应用版本后既有 Wiki 文档、Skill 数据和索引保留。开发、验证过程不得变更用户已有 Wiki 内容。
