# Design

## Context

GitHub Actions run 41287309602 的代理测试在 `docker exec ... nginx -t` 时报告容器未运行；测试没有在清理前采集代理容器状态或日志。原脚本在 `docker run -d` 返回后立即向默认配置路径复制文件，没有检查 Nginx 是否完成启动。本机 Windows/Docker 的同一测试连续六次通过；无法据此确定 CI 那次容器退出根因。

## Goals / Non-Goals

消除可证实的未就绪配置覆盖窗口，并使退出及语法错误可诊断；保留真实后端地址变更与路径透传断言。不宣称此前 CI 故障原因，不更改生产部署、权限、缓存、数据库或任何密钥。

## Decisions

- 复制代理配置前有界等待新代理的默认 HTTP 服务实际可用；检测到容器退出或超时立即失败，不使用固定休眠或无条件重启。启动完成后再复制现有交付配置，严格执行 `nginx -t` 和 reload。
- 在启动、配置检查、reload 或请求失败时，清理本次测试资源前报告代理状态、退出码和相关容器日志；诊断获取失败不覆盖原始错误，不能泄露环境变量或凭据。仅清理由本次随机标识创建的临时资源。
- 使用本机模拟 Docker 命令控制就绪延迟和退出路径，验证序列、退出码、诊断及清理；另外运行真实 Nginx 容器回归，保持 IP 变化、不重启代理与 URL 路径原样透传的原断言。
- 负责人明确暂不移除部署 workflow 中的代理回归步骤。按共同规则，测试临时目录保留并报告准确路径及清理命令，交管理员在验收后处理；本轮专有容器及网络仍须安全清理。

## Risks / Trade-offs

本机 Docker 与 GitHub Ubuntu runner 不同；本机测试无法证明此前 CI 退出的具体原因或保证未来永不波动。失败仍应停止流水线而非启动服务器部署；不自动重跑会触发部署的 workflow。
