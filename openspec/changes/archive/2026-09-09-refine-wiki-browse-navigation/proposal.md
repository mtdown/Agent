## Why

Wiki 三栏工作区（左：空间导航 / 中：文档列表与预览 / 右：大纲或文档列表）在 `add-batch-document-import` 上线后暴露出一组浏览体验问题，共同特征是**中间栏的状态不随用户意图变化**：

- **点子文件夹不刷新中间栏。** 中间栏对文件夹取的是空间树里缓存的 `folder.documents`（`refreshBrowseDocuments()` 中 `browseDocuments.value = folder?.documents ?? []`），而不是按 `folderId` 向后端查询。更糟的是 `handleTreeSelect()` 里有 `if (!isSearchMode.value)` 这道门——只要关键词框里有字，点击左侧任何节点中间栏都毫无反应。用户点子文件夹时期望中间栏立刻回到该文件夹的列表，实际可能纹丝不动。
- **打开文档后没有回路。** `centerMode` 切到 `preview` 之后，中间栏只剩文档正文，没有任何返回控件，也没有键盘快捷键。用户只能再去左侧点一次节点才能回到列表。
- **中间栏列表卡片的操作按钮又多又重复。** 每张卡片尾部有 5 个按钮：`打开`、`查看`、`仅预览/编辑`、`移动`、`删除`。其中 `打开` 与 `查看` 是同一个动作（`emit('open', item.id)`），纯冗余；长列表下每张卡片都挂 5 个链接按钮，视觉噪音大。同时**缺少批量操作**——要清理一个文件夹只能逐篇点删除。
- **搜索不记得当前空间。** 搜索栏的空间下拉默认停在"全部可见空间"。用户在"公开文档"空间里工作时，每次搜索都要手动重选空间。
- **文件夹的改名入口等于不存在。** 空间导航树里节点的 `⋯` 按钮写着 `opacity: 0`，必须先把鼠标悬停到该节点上才会显形。文件夹菜单里其实已经有 `重命名 / 移动 / 删除`，但用户看不到，于是以为没有。

## What Changes

1. **文件夹选择改为按 `folderId` 查询后端。** `refreshBrowseDocuments()` 在选中文件夹时调用 `listDocumentWikiVisByPageWithCacheUsingPost({ folderId, spaceId })`（后端 `DocumentWikiQueryRequest.folderId` 已支持），不再读取树缓存。三种选择（空间 / 文件夹 / 聚合）统一每页 20 条并渲染分页器。
2. **点击空间树即退出搜索。** `handleTreeSelect()` 无条件清空关键词、重置分页并刷新浏览列表；搜索态下点节点不再被 `isSearchMode` 短路。
3. **中间栏增加返回入口。** 预览态文档头部加"← 返回列表"按钮；同时注册全局 `Escape` 快捷键，编辑器态先退出编辑、预览态回到列表，输入框/弹窗聚焦时不拦截。
4. **操作职责重新分区。** 中间栏列表卡片去掉全部操作按钮（仅保留标题点击打开）；打开文档后的头部保留 `移动 / 编辑 / 删除` 并补上返回；右栏在列表模式下提供【文档列表 + 管理】——点"管理"进入勾选态，支持全选与底部 `移动 / 删除 / 取消`，这就是批量删除的载体。
5. **搜索默认当前空间。** 空间下拉框随当前选中空间自动同步，显示 `公开文档 / 公开文档` 这样的路径标签，可手动清除恢复"全部可见空间"。
6. **空间导航的 `⋯` 常驻可见。** 默认 `opacity: 0.55`，悬停/聚焦时为 1，文件夹的 `重命名 / 移动 / 删除` 不再需要"先 hover 才找得到"。菜单项本身不增不减。
7. 新增 `cloud_front/wikiBrowseNavigation.test.mjs` 作为静态回归，锁定上述约定不被回退。

## Non-goals

- 不改动后端接口与 SQL：`folderId` 查询、`moveDocumentWiki`、`deleteDocumentWiki` 均已满足需求，批量操作在前端串行调用即可。
- 不做递归查询：文件夹列表继续保持"只含直接归属该文件夹的文档"，与 `listFolderTree` 现有语义一致。
- 不做权限细分：文档操作按钮的可见性维持现状（不做按角色隐藏）。
- 不引入拖拽排序、批量导出等其他批量能力。
- 不改顶部导航、回收站、空间管理面板。

## Acceptance Criteria

- 中间栏处于文档预览时，点击左侧任意子文件夹，中间栏**立即**回到该文件夹的文档列表；处于搜索态时点击节点同样生效（同时退出搜索）。
- 文件夹列表数据来自后端 `folderId` 查询，与空间树缓存解耦。
- 预览态可见"返回列表"按钮，点击回到当前位置列表；`Escape` 在编辑器态退出编辑、在预览态返回列表，且焦点在输入框/弹窗时不触发。
- 中间栏列表卡片不含任何操作按钮；打开文档后头部仍可 `移动 / 编辑 / 删除`。
- 中间栏为列表模式时右栏显示【文档列表 + 管理】，进入管理态可勾选（含全选）并批量移动/删除；打开文档后右栏维持"本文大纲"，不显示管理入口。
- 搜索栏空间下拉默认选中当前空间；选中"公开文档"聚合节点时回落为"全部可见空间"。
- 空间导航节点的 `⋯` 默认可见（无需 hover）；文件夹节点的菜单含 `新建子文件夹 / 重命名 / 移动 / 删除`，空间节点仍只提供 `新建文件夹`。
- 中间栏选中文件夹时按每页 20 条分页展示，行为与空间/聚合两种选择一致；左侧空间导航树保持一次性返回整棵树、不分页、不截断。
- 右栏管理态的全选只覆盖当前页可见文档，底部显示已选条数。
- `cloud_front` 现有测试全绿，`vue-tsc --build` 退出码 0，新增回归测试通过，`openspec validate --strict` 通过。
