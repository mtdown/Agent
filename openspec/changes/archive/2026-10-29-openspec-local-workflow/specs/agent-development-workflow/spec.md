# Spec Delta

## MODIFIED Requirements

### Requirement: 验收和重大风险
测试 MUST 为每项验收记录实际操作、预期、实际和证据；清单外重大回归 MUST 单独报告并阻断交付，风格意见不得作为失败依据。环境、权限或独立实例阻止执行时 MUST 为 BLOCKED，其他无法判断或未执行时 MUST 为证据不足，均不能作为 PASS。

#### Scenario: 验收外发现重大回归
- **WHEN** 测试发现有证据支持的重大回归但它未列入固定验收
- **THEN** 测试记录风险与证据，总管暂停上传并仲裁或升级，不擅自更改固定验收

#### Scenario: 验收证据不充分
- **WHEN** 验证无法执行或结果不能证明预期行为
- **THEN** 环境、权限或独立实例阻断时结论为 BLOCKED，其他无法判断或未执行为证据不足，均不是 PASS

### Requirement: 修复循环和记录
测试失败 MUST 附原始证据与复现条件交还开发；每次修改后的复测 MUST 新建测试实例，同一原子任务最多三轮，第三轮仍失败须停止并上报。开发普通已解决错误 MUST 留存过程记录供测试者独立查阅和汇总，不逐条主动向总管上报；需求、对外行为或设计需要变化时 MUST 及时上报总管。开发不能继续时 MUST 交付 BLOCKED 状态。

#### Scenario: 修复后复测
- **WHEN** 开发完成失败修复
- **THEN** 总管提供原固定验收及新的被测快照，派发全新测试实例

#### Scenario: 普通试错已解决
- **WHEN** 开发解决不涉及需求、对外行为或设计变化的普通错误
- **THEN** 开发保留真实记录但不逐条打断总管，测试者独立查看并汇总

### Requirement: OpenSpec 全流程编排
总管 MUST 使用项目本地 OpenSpec 技能编排探索、规划、实施、规格同步和归档；总管创建 change，local propose 使用已有 change，开发 local apply 仅实施派发任务且不勾选；独立验收 PASS 后总管标记完成；所有阶段通过并验证规格同步后方可归档。原版技能 MUST 保留。

#### Scenario: 已授权的完整开发任务
- **WHEN** 用户要求完成包含规划、开发和交付的任务
- **THEN** 总管按既有工作区规则准备分支并创建 change，组织 local explore 和 propose，派发开发执行 local apply，独立测试通过后继续同步规格和归档，无须重复请求已明确的授权

#### Scenario: 独立测试失败
- **WHEN** 固定验收失败
- **THEN** 总管记录失败并安排修复，固定验收保持不变，修复后由新测试实例验证；允许记录任务状态、修复与复测，需求、对外行为或设计变化时更新相关规划工件

#### Scenario: 规格同步不成功
- **WHEN** 主规格同步失败或结果无法核实
- **THEN** 不归档并报告阻塞及证据
