## Context

参见 proposal.md。当前检索已具备向量、词法、融合和可插拔重排；本变更重点是提升多跳题的候选覆盖和证据完整性，同时保持现有链路可回退。英文评测中比较题和时序题的失败主要表现为多来源或多日期证据未同时进入最终上下文。

## Goals / Non-Goals

**Goals:**

- 用独立查询分支验证模拟答案和问题改写对候选覆盖的增益。
- 用最多两轮、有边界的 chunk 组装恢复局部上下文并保留多文档结构。
- 用可重复评测决定默认 K 和是否启用增强。

**Non-Goals:**

- 不把模拟答案当作知识库事实或最终回答依据。
- 不在本变更中重写 embedding、reranker 或权限模型。
- 不直接把不同来源文章拼成无法区分来源的单一 chunk。

## Decisions

1. **多查询采用独立分支后融合。** 原问题保留最高权重；模拟答案和问题改写作为增益分支，失败可单独回退。相比拼接为一个查询，这能隔离错误生成内容并方便 A/B 评测。
2. **两轮整理采用“同文合并、跨文分组”。** 同文相邻 chunk 物理组装以恢复上下文；跨文档只建立证据组，以保留来源和日期边界。相比无条件语义合并，这能降低事实混淆风险。
3. **候选池与最终上下文分离。** 第一轮粗排对每道题固定取 50 个 chunk；在额度约束下只计算 `recall@6` 和 `recall@10`。这里的 50 是粗排候选池深度，6/10 是最终评测 K；每文档设置占用上限，并按文档覆盖和相关性共同选择。
4. **默认策略通过评测决定。** 先保持增强关闭作为基线，只有在目标题型准确率提升、拒答下降且 p95 与 token 成本可接受时才逐项启用。
5. **采用两级固定评测协议。** 每次方案比较使用同一批 600 道英文题执行检索层评测，只记录候选覆盖、oracle、recall@K 和耗时；从这 600 题中按题型和难度固定抽取 100 题，只有候选方案才执行答案生成与 LLM 判官。两批题均不得每轮重新随机抽样。
6. **设置额度门控。** 方案必须先在 600 题检索评测中相对基线改善目标指标或验证明确假设，才进入 100 题答案评测；无明显收益的方案不继续消耗生成和判官额度。

7. **固定模块职责。** 快速 LLM（默认 `qwen3.8-flash`）只负责生成一个问题改写和一个模拟答案；embedding 模型只负责向量化；BM25 只负责词法召回；规则引擎只负责同文相邻 chunk 的合并；现有 reranker 负责合并后证据块的相关性排序；最终回答 LLM 只负责基于最终证据生成回答或拒答。任何模块不得越权替代另一个模块。
8. **固定第一轮合并规则。** 仅当两个候选满足 `docId` 相同、`chunkIndex` 间距不超过 1、章节路径相同或父级相同、合并后不超过 3600 字符且合并块不超过 3 个原始 chunk 时，规则引擎才可物理合并。合并块必须保留全部原始 chunk 标识和最高/来源分数。
9. **固定第二轮分组规则。** 不同 `docId` 的候选不得物理拼接；只有在共同覆盖同一查询实体或子条件，且来源、日期等元数据仍可独立记录时，才能建立证据组。第二轮不再递归合并，也不使用 LLM 逐对判断 chunk 是否相似。
10. **相似性判断边界。** 通用 embedding 相似度只能用于候选排序或证据组辅助评分，不能单独触发物理合并；最终是否入选由 reranker 和文档覆盖约束共同决定。

## Risks / Trade-offs

- [生成查询错误] → 限制为一个模拟答案和一个改写，降低权重并保留原问题保底。
- [上下文膨胀] → 设置合并块最大长度、最终 K 和单文档上限，记录 token 与 p95。
- [跨文档事实混淆] → 只分组不抹除来源，重排和答案提示必须保留来源/日期元数据。
- [recall 提升但正确率不升] → 将问题定位转向证据组织和答案判定，不继续盲目扩大 K。
- [样本变化导致结论不可比] → 保存固定的 600 题检索集和 100 题答案子集，并对所有方案复用。
- [答案评测额度不足] → 先跑 600 题检索指标，只有通过门槛的方案才运行 100 题答案测试。
- [职责交叉导致难以归因] → 固定快速 LLM、规则引擎、embedding、BM25、reranker 和回答 LLM 的职责，分别记录阶段输出。
- [错误合并不同事实] → 跨文档只建立带来源边界的证据组，禁止物理拼接；同文合并只允许相邻、同章节且有长度上限的 chunk。

## Migration Plan

通过配置开关逐项灰度：原流程 → 仅多查询 → 仅 chunk 整理 → 两者组合。任一阶段指标退化时关闭对应开关即可回退到现有流程。

评测数据固定保存为两份可复用输入：`mhr-eval-600-fixed.jsonl` 与 `mhr-answer-100-fixed.jsonl`。100 题应覆盖推理、比较、时序和拒答题型，并在报告中注明各题型数量。
