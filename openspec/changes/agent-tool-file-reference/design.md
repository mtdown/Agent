# Design

## Context

Cloud 存储个人文件，Agent 通过共享密钥和当前用户身份调用 Cloud；现有文件读写整体加载且写入方法串行。AI 助手已有 Wiki 引用、会话历史与右侧预览。部署为小型单机，现有个人文件持久卷须保留。

## Goals / Non-Goals

目标是提供有界读取与可靠引用、工具错误与事件，并保留未来替换存储和缓存的边界。非目标见 proposal；本次不引入任意代码执行、MCP、二进制预览或历史版本存储。

2026-10-30 负责人决定不开发 AUDIT-003 所涉及的异常中断后的操作结果恢复，执行中断由用户重新发起任务；不承诺重试去重或恢复以前的成功操作。完整资源控制和缓存扩展、整体验收与上传暂缓；文件操作仍须实施本功能必需的大小限制、授权、数据完整性与基本隔离。

## Decisions

1. 文件容量按 UTF-8 字节计上限 50 MiB；持久存储按用户隔离，沿用已有相对路径约束。抽象 metadata/read/write 接口，初始仍使用本地持久卷；不把原始磁盘路径提供给浏览器。大内容写入使用有界流与临时文件，成功校验后替换；兼容原有 create/overwrite/append 契约，超过上限无部分提交。单次大请求的上游大小限制必须与新契约匹配；Agent 模型单轮输出仍受模型限制，不能承诺一次生成 50 MiB。
2. 文件信息返回版本标识及大小；分段采用绑定用户、文件和版本的游标，返回前后续位置。读取限制在可配置上限，正确处理 UTF-8 跨边界和超长行；搜索采用有界、可续传的顺序扫描。兼容旧 read_file：小文件完整读取，大文件返回明确的分段指引。工具输出上限与分段上限协调，避免读完即触发全局上限。
3. 引用是服务端验证过、按会话消息持久化的结构化信息，关联文件、版本和偏移，模型文本中的标记仅映射真实元数据。会话所有权和文件所有权每次预览复核，失权拒绝；内容变化时明确提示，不保留历史文件版本。复用现有右侧面板，但以分段接口加载而非一次渲染整份文件；记录和重放引用时保留现有 Wiki/RAG 引用。
4. Cloud BaseResponse 的 code/message/data 贯通 Agent；已知业务异常保留原码。Agent 本地错误归入既有错误类别，调用超时且写入状态不明时标记 unknown，禁止自动重试写入。结构化结果保留兼容适配，避免破坏现有 Wiki 投影和模型工作流。事件仅记录操作名、结果类别、耗时、请求关联标识，不默认记录文件正文和密钥。
5. 工具声明和执行前校验共享契约，处理非法字段、类型和枚举；按只读/写入及领域分类并保留权限后端复核。Agent 通用循环与 Wiki 流程逐步解耦；既有选择/结果安全投影仍由程序执行，不依赖 Skill 文本。
6. 单机读、写、搜索使用有界并发和等待上限，同文件写入协调，不同文件互不串行；并发写需版本冲突保护。留存储及缓存接口，初期不缓存正文、不强制 Redis；可选的有界元数据缓存以用户、文件、版本为键且鉴权先于缓存。限制配置、耗时、失败、字节量和排队指标须可观测。多实例共享存储及跨进程锁不在本期承诺。

7. Wiki 多次写入使用按调用区分的结果集合，记录每次成功、失败及未知状态及已确认的文档标识；既有单结果历史保持兼容。显示当前文档位置时，经当前权限校验，以 SQL 从 `document_wiki.folderId` 关联 `wiki_folder.id` 并沿父级查询路径，根目录和逻辑删除显式处理；不将聊天中的名称或路径当作当前归属的权威。若文档已经移动或重命名，显示当前数据库关系；需要当时位置时须明确标注历史快照。未知写入不得凭名称猜测关联。用户只见安全名称和操作，不展示内部 ID；权限失效或文档不存在时不返回路径。多文档使用批量或有界查询，避免 N+1 和无界祖先遍历。避免存储需要随每次目录更名批量更新的完整路径；若将来增加缓存须鉴权后读取并处理移动、重命名与失效。

SQL 每批最多 50 个 ID，分批处理而非限制结果总数；祖先链最多 256 层，使用访问集合阻止循环、跨空间、失效或缺失链。无效链只让该条路径显示不可用，保留对应操作状态，不影响其他结果；文档的查看仍需复核当前权限和有效位置。

8. 只读 Wiki 查询及计划的内部 ID 不能进入普通模型输出或提示词。Agent 每次运行建立隔离的不透明别名表，模型可见的工具结果使用本轮别名，真实 ID 仅存在内部事件及服务端绑定；后续工具参数须经本轮映射验证并还原，未知/跨轮别名拒绝。用户已选空间由绑定后的工具提供别名，不将真实 ID 放进提示词。无写入或选择的只读对话保留正常回答；写入或选择结果仍由 Cloud 验证并安全投影。分页、现有 Skill 和历史选择均需回归，不能以提示词或简单的输出正则代替隔离。

## Risks / Trade-offs

- [文件在读取中变化] → 验证版本，发生变化返回明确冲突，不拼接不同版本的片段；历史引用不保留旧内容。
- [外部进程替换路径或符号链接] → 限定根目录、禁止穿越和符号链接、重新校验并测试文件替换窗口；不承诺跨进程安全直到验证。
- [50 MiB 写入、并发搜索挤占内存] → 分段流式处理、限制并发和队列；测量峰值与失败恢复，不预设性能达标。
- [写入后超时] → 返回结果未知，不自动重试；验证文件和操作状态再恢复。
- [摘要/引用被模型伪造] → 仅渲染服务端绑定当前用户和消息的真实引用。

## Migration Plan

沿用持久卷和既有文件；逐步部署 Cloud、Agent、前端并保持旧调用可用。若新增持久化结构，迁移必须幂等并记录回滚；回滚停用新入口、恢复旧版本，保留文件卷与历史消息，不删除用户文件。大文件超过旧版上限时回滚后的旧读取可能受限，须明确告知。
