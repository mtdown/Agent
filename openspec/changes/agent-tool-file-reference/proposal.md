# Proposal

## Why

Agent 的文件工具只能整体读取不超过 1 MiB 的文本，工具错误码也未贯通调用链。用户需要在低内存服务器上使用较大个人文件、可靠地查看工具结果，并通过会话引用定位原文。

## What Changes

- 个人 UTF-8 文本文件上限调整为 50 MiB，提供有界分段读取、搜索和安全的增量写入；保留现有文件和小文件工具兼容性。
- Agent 回答支持有权限、可持久化的个人文件片段引用，在已有右侧预览中分段展示并定位；文件变化后明确提示，绝不展示错误位置。
- 修复同轮多次 Wiki 写入结果错配或覆盖：逐项记录操作结果，通过 SQL 查询文档与文件夹的当前关系；排查相似的单组状态覆盖风险。
- 工具结果和错误沿用项目业务错误码，区分失败、成功与写入结果未知；保留实际执行结果和必要过程信息。
- 为工具参数校验、分类、执行追踪、文件存储、缓存与并发控制建立简单边界；优先使用单机有界资源，不强制引入新基础设施。
- 负责人于 2026-10-30 指定优先实施工具调用规范、个人文件及文件引用页面；完整资源控制/缓存扩展、全项目集成验收、归档和上传暂缓。异常中断后已执行操作的重建或恢复机制（AUDIT-003）不在本次开发范围，用户可重新发起任务；保留风险记录，不声称已修复。
- 非目标：执行 Python/Java 任意代码、实现 MCP/CLI 集成、二进制文件或历史文件版本、建设分布式平台。

## Capabilities

### New Capabilities
- `agent-tool-reliability`: Agent 工具调用的可校验契约、结果、错误和过程反馈。
- `agent-personal-file-reference`: 个人文本文件的有界存储读取、引用与预览。

### Modified Capabilities
- `ai-assistant-chat`: 在已有会话中支持持久化且可点击的个人文件引用。

## Impact

涉及 Cloud 个人文件存储、内部工具接口和公开的授权预览接口、Agent 工具注册和循环、会话历史、前端引用与预览，以及针对超时、权限和并发的测试。预期可能需要调整请求大小配置；生产部署需要保留现有个人文件持久卷。任何接口、数据库或依赖变化须在设计和开发任务卡中明确。
