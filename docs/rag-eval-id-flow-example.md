# RAG 评测题的 ID 对应流程

本文用项目第一版评测集中的真实题目 `A-p-02-2`，从文章一路追到最终检索证据。这个例子包含两份文章：政策解读文章提供问题，政策原文是系统检索答案时的目标文档。

## 【文章】

**问题来源文章（政策解读）**

- 标题：《重庆市推进空中丝绸之路建设实施方案》政策解读
- 语料侧 `metadataId`：`15345784`
- 知识库侧 `docId`：`2097637772185948161`

**目标文章（政策原文）**

- 标题：重庆市人民政府办公厅关于印发《重庆市推进空中丝绸之路建设实施方案》的通知
- 语料侧 `metadataId`：`15304046`
- 知识库侧 `docId`：`2097637762685849602`

`metadataId` 标识语料目录中的文档元数据；`docId` 标识知识库中的文档。导出锚点映射时，程序用规范化标题把它们对应起来。

## 【第一次匹配】

程序从两篇标题中都识别出政策名称“重庆市推进空中丝绸之路建设实施方案”，于是把它们建立为一组配对：

```text
pairId         = p-02
policyDocId    = 2097637762685849602
interpretDocId = 2097637772185948161
```

`pairId=p-02` 是这对文章关系的编号。它表示“哪篇解读对应哪份政策原文”，不是 chunk 编号。

## 【第二次拆分】

针对 `p-02`，第一版出题流程从政策解读文章生成两道问题：一道概览题、一道细节题。问题 ID 按 `A-{pairId}-{序号}` 生成：

| 问题 ID | 题目类型 | 问题 |
|---|---|---|
| `A-p-02-1` | 概览 | 重庆市推进空中丝绸之路建设实施方案主要包含哪些方面的支持措施？ |
| **`A-p-02-2`** | **细节** | **重庆在货物通关方面有哪些具体的便利化措施和时间保障？** |

这里“拆分”指一组文章配对生成多道独立评测题。每道题有自己的问题 ID，但都保留来源 `pairId=p-02`，因此还能追溯回这两篇文章。

## 【第二次匹配】

现在对问题 `A-p-02-2`，程序要从**政策原文**里找出能支持答案的 chunk。它先根据问题、答案、解读文章中的原文摘录和关键词，对政策原文的 chunks 做粗排，再让模型从候选段落中挑选证据，并检查摘录是否确实出现在该段原文中。

本题粗排候选顺序为：`5, 3, 4, 2, 1, 8, 6, 9, 0, 10, 7`。第一个候选就是政策原文的 `chunkIndex=5`，最终 gold 中对应：

```text
question id     = A-p-02-2
gold docId      = 2097637762685849602
gold chunkIndex = 5
database chunkId= 2098672269408964615
```

该段原文是：

> 实施机坪“空空直转”“空侧直通”等措施，强化“7×24小时”通关保障，开通特殊进口商品绿色通道，实现快验快放。

所以这道题完整的 ID 轨迹是：

```text
解读文章 metadataId 15345784
  → 解读文章 docId 2097637772185948161
  → 与政策原文 docId 2097637762685849602 建立 pairId p-02
  → 生成问题 ID A-p-02-2
  → gold 指向政策原文 docId 2097637762685849602 的 chunkIndex 5
  → 该 chunk 当前数据库主键 chunkId 2098672269408964615
```

### 为什么 gold 保存 `docId + chunkIndex`

评测题里的 gold 使用 `docId + chunkIndex`，即“哪篇文档的第几个 chunk”。数据库 `chunkId` 是当前索引行的主键；索引重建时，旧行可能失效并插入新行，主键会变化。用逻辑坐标作为评测锚点，更容易在重建索引后重新映射证据。

### 数据来源

- 第一版题目：`eval/golden.v1.jsonl` 中的 `A-p-02-2`
- 第一版配对和出题逻辑：`eval/scripts/build_pairs.py`、`eval/scripts/generate_pair_questions.py`
- 文档与 chunk 映射：生成时的 `eval/tmp/anchor-map.json`

这个例子说明：解读文章产生问法，政策原文提供目标证据；`pairId` 串起两份文章，问题 ID 标识某一道题，gold 坐标再把这道题连到目标文章的具体 chunk。
